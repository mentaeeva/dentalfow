# DentaFlow

Интерактивный прототип CRM для взаимодействия зуботехнических лабораторий, стоматологических клиник и зубных техников. Сделан по техническому заданию DentaFlow v2.0 (Multi-Laboratory Dental CRM) для Assignment 5.

**Демо:** https://mentaeeva.github.io/dentalfow/

**Общая база и загрузка файлов:** приложение может использовать Supabase Postgres + Storage с GitHub Pages. Инструкция: [SUPABASE_SETUP.md](SUPABASE_SETUP.md). Пока `docs/js/backend-config.js` не заполнен, работает локальный демо-режим.

Прототип показывает полный жизненный цикл заказа: оформление, назначение техников, изготовление, доставка, подтверждение получения, переделка и финансовые расчёты. Всё это в одной системе вместо мессенджеров и таблиц.

## Запуск

Сборка и установка зависимостей не нужны.

- **Просто открыть:** двойной клик по `index.html`.
- **Локальный сервер** (например, чтобы открыть с телефона в той же сети):
  ```bash
  python -m http.server 8000
  ```
  Затем откройте http://localhost:8000.
- **GitHub Pages:** Settings → Pages → Source: `Deploy from a branch` → ветка `main`, папка `/docs`. Через минуту прототип будет доступен по адресу https://mentaeeva.github.io/dentalfow/.

## Что реализовано

- **Авторизация.** Роль определяется по логину, кабинет открывается автоматически, сессия сохраняется после обновления страницы.
- **Многолабораторность.**
  - Клиника выбирает лабораторию при оформлении, цены и услуги берутся из прайса именно этой пары «клиника + лаборатория».
  - Администратор видит только свою лабораторию. Попытка открыть чужой заказ по ID показывает «Нет доступа».
- **Кабинет клиники.**
  - Поиск по ФИО и ID, фильтры по лаборатории, статусу и периоду, сортировка и группировка по лабораториям.
  - Создание и изменение заказа, отмена в статусе «Отправлено».
  - Массовое подтверждение получения с отдельной галочкой на каждый заказ.
- **Кабинет администратора.**
  - Вкладки статусов со счётчиками, назначение и переназначение техников (максимум двое), передача на доставку пакетом.
  - Отмена с обязательной причиной и скриншотом, ручной перенос между разделами с причиной.
  - Заказы для разовых клиник.
- **Кабинет техника.** Свои заказы, завершение работы с выбором услуг по личным ставкам, отчёт о проделанной работе.
- **Переделки.**
  - ID заказа сохраняется, создаётся новый цикл выполнения.
  - История всех циклов доступна только для чтения.
  - Администратор утверждает оплату переделки: полная, частичная или нулевая.
- **Справочники.** Базовые и индивидуальные цены клиник, ставки техников. Изменения не пересчитывают уже оформленные заказы.
- **Отчёты.** Зарплаты техникам и расчёты с клиниками за период: предпросмотр A4, копирование таблицы в Excel.
- **Прочее.** Адаптивная вёрстка (desktop, tablet, mobile), форма обратной связи «Оцените удобство», кнопка сброса демо-данных.

## Структура

```
index.html        разметка и подключение файлов
css/styles.css    стили: палитра и размеры из раздела 2.3 ТЗ
js/utils.js       иконки, форматирование дат и сумм, расчёт срока сдачи
js/store.js       локальное хранилище и доменные действия (заказ, назначение, доставка, переделка…)
js/cloud.js       синхронизация снимка приложения и файлов через Supabase
js/backend-config.js URL проекта Supabase и публичный anon/publishable key
supabase/schema.sql схема таблицы, Storage и политики для демо
js/seed.js        демонстрационные данные
js/views.js       отрисовка всех экранов и модальных окон
js/app.js         обработчики действий, навигация, запуск
```

Подход:
- **Данные** лежат в одном объекте; `localStorage` даёт локальный режим и копию браузера, а настроенный Supabase синхронизирует общий снимок через PostgreSQL.
- **Состояние меняют только функции из `store.js`.** Каждая сама записывает событие в историю заказа.
- **Интерфейс перерисовывается целиком** из текущего состояния (функция `view()`).

## Ограничения прототипа

Это учебный прототип, а не production-система (раздел 17 ТЗ):

- **Supabase подключается отдельно.** Создание проекта и заполнение `backend-config.js` нужны для общей БД и постоянных файлов.
- **Текущие политики Supabase открыты для демонстрации.** Любой посетитель может читать и менять состояние и файлы; демо-логины не обеспечивают безопасность.
- **Не загружайте реальные данные пациентов.** Для production нужны реальная аутентификация, серверная изоляция клиник и лабораторий и приватные файлы.
- **Экспорт в PDF** запланирован для полной версии.
- **Все данные вымышленные.**

Для полной версии ТЗ рекомендует React + TypeScript, FastAPI или Node.js, PostgreSQL и Docker.
