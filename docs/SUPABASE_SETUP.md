# Подключение общей БД и файлов к GitHub Pages

Страницы остаются статическим сайтом. Postgres и Storage предоставляет Supabase; сервер и сборка не нужны.

## Настройка

1. Создайте проект в Supabase.
2. Откройте **SQL Editor**, вставьте `docs/supabase/schema.sql` и выполните скрипт.
3. В **Project Settings → API** скопируйте Project URL и anon/publishable key.
4. В `docs/js/backend-config.js` вставьте эти два публичных значения в `supabaseUrl` и `supabaseAnonKey`. Не используйте `service_role` или secret key в браузере.
5. Отправьте изменения в GitHub. GitHub Pages продолжит публиковать ветку `main`, папку `/docs`. Через минуту откройте сайт с двух устройств: изменения заказов синхронизируются в общей БД, файлы загружаются в Storage.

Если оставить `backend-config.js` пустым, приложение работает в прежнем локальном демо-режиме. Новая база начинает работу с демонстрационных данных; если таблица уже содержит состояние, приложение использует его вместо локальной копии.

## Ограничение безопасности

SQL-политики намеренно открыты, чтобы текущие демонстрационные логины продолжали работать на статическом хостинге. Любой посетитель, знающий публичный URL проекта, может читать и менять общую запись, а также читать, загружать и удалять файлы. Логины приложения хранятся в коде браузера и **не являются аутентификацией**. Не используйте настоящие ФИО пациентов, медицинские снимки или другие персональные/медицинские данные.

Этот вариант даёт настоящую межбраузерную БД и постоянное файловое хранилище, но не является безопасной production-системой. Для реальных данных сначала нужны Supabase Auth, серверные роли вместо демо-входа, изоляция данных клиник и лабораторий через RLS, приватный Storage с подписанными ссылками, аудит и проверка применимых требований по медицинским данным. Добавление только ключа anon эти требования не решает.

## Где хранятся данные

- `public.dentaflow_state` — один общий JSON-снимок данных прототипа; PostgreSQL и Realtime.
- Бакет `dentaflow-files` — файлы заказов и подтверждения отмены; до 50 МБ на файл.
- Файлы доступны по публичным ссылкам в текущей демо-конфигурации.
- `localStorage` остаётся локальной копией и резервным режимом, если Supabase недоступен.

Если в Supabase уже есть данные, сохраните резервную копию до настройки. Сброс демо-данных из приложения меняет общую запись, когда облачная синхронизация включена.
